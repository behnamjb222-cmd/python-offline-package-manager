# راهنمای استفاده (فارسی)

## ۱. نصب و شروع
[INSTALL.md](INSTALL.md) را ببینید. برنامه را با `python main.py` (یا `POPM.exe`) اجرا کنید. زبان و تم را در **تنظیمات** عوض کنید.
نوار وضعیت پایین پنجره: وضعیت اینترنت، Python و pip فعال، مسیر مخازن، حجم مخزن / فضای آزاد دیسک و عملیات در حال اجرا (با دکمه‌ی **لغو**).

## ۲. ساخت مخزن آفلاین (روی سیستم دارای اینترنت)
۱. **محیط‌های پایتون ← شناسایی محیط‌ها.** اگر Python شما در فهرست نبود «افزودن دستی Python…». یکی را انتخاب و «انتخاب به‌عنوان فعال» را بزنید.
   POPM هر دستور pip را به شکل `<همان python> -m pip` اجرا می‌کند و هرگز از `pip` سراسری استفاده نمی‌کند.
۲. **اسکن پکیج‌ها ← اسکن محیط فعال.** پکیج‌های موردنظر را تیک بزنید (یا «انتخاب همه»). پکیج‌هایی که از پوشه‌ی محلی / VCS / editable نصب شده‌اند
   از مخزن اینترنتی قابل دانلود نیستند؛ در «گزارش منشأ نامشخص» دیده می‌شوند و رد می‌شوند.
۳. **ارسال انتخاب‌شده‌ها به دانلودر** (یا خودتان نیازمندی‌ها را بنویسید/بارگذاری کنید، مثل `requests==2.32.3`؛ دو خط از یک پکیج با نسخه‌های متفاوت هر دو نسخه را جمع می‌کند).
۴. **دانلود و جمع‌آوری**
   * **سیستم مقصد** — «مثل محیط انتخاب‌شده»، «مقصد مخزن» یا «سفارشی» (نسخه‌ی Python، سیستم‌عامل و معماری سیستم **آفلاین**). فایل‌های wheel به این‌ها وابسته‌اند؛ درست انتخاب کنید.
   * **مخزن مقصد** — یکی را انتخاب کنید یا «جدید…» (نام، پوشه، مقصد).
   * گزینه‌ها: شامل وابستگی‌ها، اجازه‌ی sdist (پکیج‌های سورس که روی مقصد باید ساخته شوند — به‌طور پیش‌فرض خاموش)، تعداد تلاش مجدد، دانلود هم‌زمان، حداکثر حجم، پوشه‌ی مخزن محلی (`--find-links`) به‌جای اینترنت.
   * «پیش‌نمایش (حل وابستگی)» فهرست دقیق فایل‌ها، حجم و هشدارها را نشان می‌دهد؛ «شروع دانلود» اجرا می‌کند. فایل‌های ناموفق را می‌توان دوباره امتحان کرد.
   * اگر برای مقصد wheel سازگار وجود نداشته باشد پیام روشن می‌گیرید و بی‌صدا از سورس ساخته نمی‌شود.
۵. **اعتبارسنجی فایل‌ها ← بررسی همه‌ی فایل‌ها** همه را دوباره هش می‌کند. **بررسی سازگاری** هر فایل را با مقصد می‌سنجد.
۶. **انتقال و خروجی ← ساخت بسته**: مخزن، (اختیاری) فهرست پکیج‌ها (وابستگی‌ها خودکار اضافه می‌شوند)، مقصد، اندازه‌ی قسمت‌ها و خروجی را مشخص کنید. ZIP پس از ساخت اعتبارسنجی می‌شود. آن را روی فلش کپی کنید.

## ۳. نصب روی سیستم آفلاین
**روش الف — اسکریپت مستقل (نیازی به POPM نیست، Python باید نصب باشد):**
```
فایل zip را استخراج کنید، سپس در همان پوشه:
python install_offline.py --dry-run                      # فقط نمایش
python install_offline.py --venv C:\envs\myproject        # پیشنهادی: محیط مجازی جدید
```
اسکریپت checksum ها را بررسی می‌کند، اگر نسخه‌ی Python با مقصد بسته فرق داشته باشد هشدار می‌دهد، تأیید می‌گیرد (`--yes` برای رد کردن پرسش)،
`pip install --no-index --find-links packages -r manifests/requirements.txt` را اجرا و سپس `pip check` را اجرا می‌کند.

**روش ب — رابط گرافیکی POPM:**
۱. «انتقال و خروجی ← وارد کردن بسته» (فایل `.zip` یا اولین قسمت `.zip.001`) داخل یک مخزن.
۲. «نصب آفلاین»: مخزن را انتخاب کنید، پکیج‌ها را تیک بزنید (یا نیازمندی‌ها را بنویسید)، **محیط مجازی جدید** (مسیر + Python پایه) یا محیط موجود را انتخاب و گزینه‌ها را تنظیم کنید و «بررسی و نمایش خلاصه» را بزنید.
۳. خلاصه را بخوانید (پکیج‌ها، نسخه‌ها، سازگاری، گزینه‌ها، هشدارها). هنوز **هیچ چیز تغییر نکرده**. برای تأیید «هم‌اکنون نصب کن» را بزنید.
۴. نتیجه‌ی هر پکیج نمایش داده می‌شود، مسیر فایل گزارش نشان داده می‌شود و «تلاش مجدد ناموفق‌ها» و «بررسی نصب» در دسترس‌اند.
   «نصب آزمایشی» کل مجموعه را در یک venv موقت امتحان می‌کند که بعد حذف می‌شود.

توضیح گزینه‌ها: `--only-binary` ساخت از سورس را رد می‌کند (بدون کامپایل روی مقصد)؛ `--no-deps` وابستگی‌ها را نصب نمی‌کند (توصیه نمی‌شود، POPM هشدار می‌دهد)؛
`--upgrade` و `--force-reinstall` مثل pip. نصب در Python سراسری سیستم ممکن است دسترسی مدیر بخواهد — venv جدید بهتر است.

## ۴. صفحه‌های دیگر
* **مخازن آفلاین** – فهرست/جست‌وجو/فیلتر، افزودن دستی فایل، پنهان/بازگردانی/حذف (حذف دائمی تأیید می‌خواهد)، بررسی سلامت، تکراری‌ها، پشتیبان‌گیری/بازیابی فراداده، وارد کردن پوشه‌ی مخزن موجود، گزارش، باز کردن پوشه.
* **اعتبارسنجی فایل‌ها** – بررسی SHA-256، منشأ فایل‌ها (آدرس منبع، مبدأ هش)، گزارش فضا، پاک‌سازی فایل‌های موقت، حذف فایل‌های بدون ارجاع.
* **گزارش‌ها** – همه‌ی عملیات (نوع، وضعیت، خلاصه) با لاگ؛ خروجی TXT/JSON؛ حذف گزارش‌های قدیمی.
* **تنظیمات** – پوشه‌ها، تلاش مجدد، هم‌زمانی، محدودیت‌ها، زبان، تم، سطح لاگ، مدت نگهداری، Proxy (رمز فقط برای همین نشست)، Timeout، بررسی SSL (روشن بماند)، CA bundle، Python پیش‌فرض، سیاست sdist.

## ۵. نکته‌ها
* checksum نشان می‌دهد فایل پس از افزوده شدن تغییر نکرده؛ ناشر را ثابت نمی‌کند. فهرست منشأ هش‌هایی را که از مخزن اینترنتی آمده‌اند با `index` نشان می‌دهد.
* نصب موفق تضمین نمی‌کند پکیج هنگام اجرا درست کار کند (کتابخانه‌های سیستمی، درایور GPU و ...).
* بسته **شامل Python نیست**. روی سیستم آفلاین باید Python با همان نسخه‌ی فرعی، سیستم‌عامل و معماری مقصد از قبل نصب باشد.
